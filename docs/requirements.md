# 要件定義書：家計簿（収支管理）アプリ

## 1. 概要

日々の収入・支出を記録し、家計を把握するための個人向け家計簿アプリを作成する。

## 2. 背景・目的

自主学習・ポートフォリオ用の個人プロジェクトとして、以前作成したTrello風タスク管理アプリ（React + Spring Boot + PostgreSQL）と同じ技術スタックでCRUD（作成・読み取り・更新・削除）操作を再度練習する。加えて、前作では扱わなかった「月別・カテゴリ別の集計表示」に新たに挑戦し、単純なCRUDを超えた画面・API設計を学習する。

## 3. 対象ユーザー

- 自分1人で家計を管理したい人
- 複数人での共有・同時編集は想定しない

## 4. データ項目（イメージ）

### 4.1 収支記録

| 項目 | 内容 |
|---|---|
| ID | 一意な識別子（自動採番） |
| 日付 | 取引が発生した日（入力日とは区別する） |
| 金額 | 正の整数（円単位）で保持し、種別で収入/支出を区別する |
| 種別 | 収入 / 支出 |
| カテゴリ | 種別に紐づくカテゴリ（4.2参照） |
| メモ | 任意入力、500文字以内 |
| 作成日時・更新日時 | システムが自動記録 |

### 4.2 カテゴリ

| 項目 | 内容 |
|---|---|
| ID | 一意な識別子（自動採番） |
| 名称 | 1〜20文字、同一種別内で重複不可（例：食費、交通費、給与など） |
| 種別 | 収入用 / 支出用（カテゴリは種別ごとに独立して管理する） |

## 5. 機能要件

| No. | 機能 | 内容 |
|---|---|---|
| 1 | 収支記録の作成 | 日付・金額・種別・カテゴリを入力して新規記録を追加できる（メモは任意）。種別を選ぶと、その種別に属するカテゴリのみが選択肢に表示される |
| 2 | 収支記録の一覧表示 | 日付の新しい順を初期表示順とする。初期表示期間は当月分とする（No.5の絞り込みで期間を変更可能） |
| 3 | 収支記録の編集 | 既存記録の日付・金額・種別・カテゴリ・メモを変更できる。種別を変更した場合、カテゴリ選択肢も切り替わる |
| 4 | 収支記録の削除 | 不要になった記録を削除できる（削除前に確認ダイアログを表示する） |
| 5 | 一覧の絞り込み・並び替え | 期間（開始日〜終了日）・種別・カテゴリで絞り込みできる。日付・金額を基準に昇順/降順で並び替えできる |
| 6 | カテゴリ管理 | カテゴリの追加・編集・削除ができる。カテゴリは収入用／支出用で独立した一覧として管理する（4.2参照）。既存の収支記録に紐づいているカテゴリは削除できない（削除しようとした場合はエラーメッセージを表示する） |
| 7 | 月別・カテゴリ別の合計金額表示 | 対象月を選択すると、その月のカテゴリ別合計（収入・支出それぞれ）を表形式とグラフ（円グラフ等）の両方で表示する。あわせて月次サマリーとして「収入合計」「支出合計」「差引（収支）」を表示する |
| 8 | 入力値のバリデーション | 金額は1以上の整数のみ許可し、必須項目（日付・金額・種別・カテゴリ）が未入力の場合は登録できない。メモは任意、500文字以内 |

### 5.1 補足

- 収支記録の識別は内部的なID（作成時に自動採番）で行う。
- カテゴリは種別（収入用／支出用）ごとに独立した一覧を持ち、記録作成・編集時は選択した種別に応じたカテゴリのみが選択肢となる。
- 一覧の初期表示期間を「当月」とするのは、家計簿は日々記帳する性質上、無期間だとレコード数が多くなりやすいため（6.1参照）。

### 5.2 実装状況

各機能要件の実装状況。バックエンド（Spring Boot API）・フロントエンド（React）の両方がそろって初めて「完了」とする。実装が進むたびに更新する。

| No. | 機能 | ステータス |
|---|---|---|
| 1 | 収支記録の作成 | 完了（プロトタイプ） |
| 2 | 収支記録の一覧表示 | 完了（プロトタイプ） |
| 3 | 収支記録の編集 | 完了（プロトタイプ） |
| 4 | 収支記録の削除 | 完了（プロトタイプ） |
| 5 | 一覧の絞り込み・並び替え | 完了（プロトタイプ） |
| 6 | カテゴリ管理 | 完了（プロトタイプ） |

| 8 | 入力値のバリデーション | 完了（プロトタイプ） |

## 6. 非機能要件

- Webブラウザ上で動作すること（最新版のGoogle Chromeを動作対象とする）
- 収支データ・カテゴリデータはバックエンドAPI経由でPostgreSQLデータベースに保存する（技術スタックは8章参照）
- 特別な性能要件（大量データ、同時アクセス等）は求めない
- スマートフォン対応は必須としない（学習目的のため今回は対象外）

### 6.1 想定データ量

家計簿は日々記帳する性質上、前作（タスク管理アプリ、数十件程度）より収支記録の件数は多くなりやすい（年間で数百〜数千件程度を想定）。この想定を踏まえ、一覧のデフォルト表示期間を当月とする（5.1参照）ことで、初期表示時に大量データを一度に扱わない設計とする。

## 7. 対象外（今回のスコープに含めない機能）

以下は今後の拡張候補とし、今回の要件には含めない。

- ログイン・ユーザー管理機能
- 複数人での共有・同時編集
- 予算オーバーのアラート通知
- レシート画像の添付
- 銀行API等の外部連携
- CSVエクスポート/インポート
- 複数通貨対応
- 公開環境への常時デプロイ（README上のスクリーンショット・動作GIFでの提示を基本とし、無料枠でのデプロイは任意の発展課題とする）
- セキュリティ要件（認証・認可、通信の暗号化など）
- アクセシビリティ対応（スクリーンリーダー対応など）

## 8. 開発環境・技術要件

前作（Trello風タスク管理アプリ）に完全準拠する。

| 区分 | 技術 | バージョン | 備考 |
|---|---|---|---|
| フロントエンド | React | 19.2.8 | 素のReactで構築する（Next.js等は対象外） |
| フロントエンド | TypeScript | 5.7.3 | |
| フロントエンド | Vite | 6.4.3 | 開発サーバー起動・ビルド用 |
| バックエンド | Java | 25 | Gradleのtoolchain設定で指定 |
| バックエンド | Spring Boot | 4.1.0 | REST APIを提供 |
| バックエンド | Gradle | 9.5.1 | プロジェクト同梱のGradle Wrapperで固定 |
| データベース | PostgreSQL | 16 | Dockerコンテナとして用意する（`docker-compose.yml`） |

全体構成：`[ブラウザ (React)] --HTTP(REST API)--> [Spring Boot] --> [PostgreSQL (Docker)]`。データはブラウザのlocalStorageではなく、バックエンドAPI経由でPostgreSQLに保存する。

（詳細な技術選定理由・グラフライブラリ選定などは、次工程で `docs/tech-stack.md` として別途整理する）

## 9. テスト方針

- 学習目的のため、AI（Claude Code）による自動テスト作成・実行を基本とする
  - バックエンド：単体テスト・結合テストを想定（JUnit等）
  - フロントエンド：単体テストを想定（Vitest等）
- 自動化が難しい箇所、または画面上の見た目・操作感を確認したい箇所（グラフ表示、ドラッグ操作等が発生する場合）は手動テストも併用する
- テストの詳細な範囲・ツール選定は、次工程（設計・実装フェーズ）で具体化する

## 10. 制約条件

- 学習目的のプロジェクトであり、実装はAI（Claude Code）と協働して進める
- 開発の全工程（要件定義・設計・実装・テスト・リリース）を経験することを重視し、まずは必要最小限の機能に絞って構築する
