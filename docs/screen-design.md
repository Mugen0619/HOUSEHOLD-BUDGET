# 画面設計：家計簿（収支管理）アプリ

要件定義書（[docs/requirements.md](./requirements.md)）5章をもとに、画面構成とレイアウトを整理する。API設計は[data-design.md](./data-design.md)を参照。

## 1. 画面構成

[tech-stack.md](./tech-stack.md)の方針通り、ルーティングは使わず1ページ内のタブ切り替えで4画面を構成する。

```
┌───────────────────────────────────────────────────┐
│  家計簿アプリ                                        │
│  [ 一覧 ] [ カテゴリ管理 ] [ 定期支出 ] [ 月次集計 ]     │ ← タブ
├───────────────────────────────────────────────────┤
│                                                     │
│           （選択中タブの画面内容）                      │
│                                                     │
└───────────────────────────────────────────────────┘
```

| No. | 画面 | 対応する機能要件 |
|---|---|---|
| 1 | 収支記録一覧画面 | No.1〜5, 8, 9（定期バッジ表示） |
| 2 | カテゴリ管理画面 | No.6 |
| 3 | 定期支出テンプレート管理画面 | No.9 |
| 4 | 月次集計画面 | No.7 |

## 2. 収支記録一覧画面

```
┌───────────────────────────────────────────────────┐
│ [+ 新規追加]                                         │
│                                                      │
│ 期間 [2026-08-01] 〜 [2026-08-31]                    │
│ 種別 [すべて ▼]  カテゴリ [すべて ▼]                    │
│ 並び替え：[日付 ▼] [降順 ▼]                            │
├───────────────────────────────────────────────────┤
│ 日付        種別   カテゴリ   金額     メモ  バッジ  操作  │
├───────────────────────────────────────────────────┤
│ 2026-08-25  支出   住居費    80,000円  家賃  [定期] [編集][削除] │
│ 2026-08-15  支出   食費      1,200円  ...           [編集][削除] │
│ 2026-08-14  収入   給与      300,000円 ...           [編集][削除] │
│ ...                                                  │
└───────────────────────────────────────────────────┘
```

- 初期表示：当月分、日付の新しい順（要件定義書5.1）
- 絞り込み条件（期間・種別・カテゴリ）・並び替え条件はフィルタ操作時に即座に一覧へ反映する（再取得はAPI `GET /api/transactions` へのクエリパラメータ変更で行う）
- 「種別」フィルタ・入力フォームの選択肢は「すべて／収入／支出」。「カテゴリ」フィルタは選択中の種別に応じて選択肢が絞り込まれる
- 「+ 新規追加」クリックでモーダルを開き、入力フォーム（日付・金額・種別・カテゴリ・メモ）を表示する。種別を切り替えるとカテゴリの選択肢が切り替わる（要件定義書5章 No.1, No.3）
- 「編集」クリックで同じモーダルに既存値を入れた状態で開く
- 「削除」クリックで確認ダイアログ（ブラウザ標準の `confirm` またはモーダル）を表示し、OK時のみ削除APIを呼ぶ（要件定義書5章 No.4）
- バリデーションエラーはフォーム内の該当項目の下にエラーメッセージを表示する（要件定義書5章 No.8）
- レスポンスの `source` が `RECURRING` の行には「定期」バッジを表示し、定期支出テンプレートから自動生成された記録であることを示す（要件定義書5章 No.9、[data-design.md](./data-design.md) 1.2）。バッジ表示以外の操作（編集・削除）は通常の記録と同じ

### 2.1 入力フォーム（新規追加・編集共通）

```
┌─────────────────────────────┐
│ 収支記録の追加/編集              │
│                              │
│ 日付   [____________]         │
│ 種別   ( ) 収入  ( ) 支出       │
│ カテゴリ [選択してください ▼]     │
│ 金額   [____________] 円       │
│ メモ   [________________]     │
│        （任意・500文字以内）     │
│                              │
│        [キャンセル]  [保存]     │
└─────────────────────────────┘
```

## 3. カテゴリ管理画面

```
┌───────────────────────────────────────────┐
│ 収入用カテゴリ                    [+ 追加]     │
├───────────────────────────────────────────┤
│ 給与                          [編集][削除]     │
│ ボーナス                       [編集][削除]     │
├───────────────────────────────────────────┤
│ 支出用カテゴリ                    [+ 追加]     │
├───────────────────────────────────────────┤
│ 食費                          [編集][削除]     │
│ 交通費                        [編集][削除]     │
└───────────────────────────────────────────┘
```

- 収入用・支出用のカテゴリを別リストとして並べて表示する（要件定義書4.2・5章 No.6）
- 「削除」をクリックし、そのカテゴリが収支記録で使用中の場合はエラーメッセージ（「このカテゴリは使用中のため削除できません」等）を表示し、削除を中止する（APIの409レスポンスに対応）
- カテゴリの種別（収入用／支出用）は作成後に変更不可（[data-design.md](./data-design.md) 1.1）とし、編集フォームでは名称のみ変更可能とする

## 4. 定期支出テンプレート管理画面

```
┌───────────────────────────────────────────────────┐
│ [+ 追加]                                             │
├───────────────────────────────────────────────────┤
│ 名称    種別   カテゴリ   金額      実行日   操作        │
├───────────────────────────────────────────────────┤
│ 家賃    支出   住居費    80,000円   毎月25日 [編集][削除] │
│ Netflix 支出   娯楽費    1,980円    毎月1日  [編集][削除] │
│ ...                                                  │
└───────────────────────────────────────────────────┘
```

- 一覧は種別（収入/支出）を問わず1つのテーブルで表示する（件数が少ないと想定されるため、カテゴリ管理画面のように収入用/支出用を分けない）
- 「+ 追加」クリックでモーダルを開き、入力フォーム（名称・種別・カテゴリ・金額・実行日・メモ）を表示する。種別を切り替えるとカテゴリの選択肢が切り替わる（収支記録の入力フォームと同様の挙動）
- 「削除」クリックで確認ダイアログを表示し、OK時のみ削除APIを呼ぶ。削除しても過去に自動生成された収支記録は残ることを、確認ダイアログの文言で伝える（例：「削除しても過去に自動生成された収支記録は残ります」）
- 一覧画面（2章）で「定期」バッジが付いた記録から、生成元のテンプレートを直接編集する導線は設けない（テンプレートの編集はこの画面から行う）

### 4.1 入力フォーム（新規追加・編集共通）

```
┌─────────────────────────────┐
│ 定期支出テンプレートの追加/編集    │
│                              │
│ 名称   [____________]         │
│ 種別   ( ) 収入  ( ) 支出       │
│ カテゴリ [選択してください ▼]     │
│ 金額   [____________] 円       │
│ 実行日 [毎月 __ 日]            │
│        （31日等、存在しない月は月末に生成） │
│ メモ   [________________]     │
│        （任意・500文字以内）     │
│                              │
│        [キャンセル]  [保存]     │
└─────────────────────────────┘
```

## 5. 月次集計画面

```
┌───────────────────────────────────────────┐
│ 対象月 [2026-08 ▼]                          │
├───────────────────────────────────────────┤
│ 収入合計: 300,000円  支出合計: 85,000円        │
│ 差引（収支）: 215,000円                       │
├───────────────────────────────────────────┤
│ 支出内訳（円グラフ）    │  収入内訳（円グラフ）    │
│      [pie chart]      │      [pie chart]      │
├───────────────────────────────────────────┤
│ 支出カテゴリ別内訳（表）                        │
│ 食費      40,000円                           │
│ 交通費    15,000円                           │
├───────────────────────────────────────────┤
│ 収入カテゴリ別内訳（表）                        │
│ 給与     300,000円                           │
└───────────────────────────────────────────┘
```

- 対象月を月選択UI（`<input type="month">` 等）で切り替えると `GET /api/summary?month=YYYY-MM` を呼び直し、表とグラフの両方を更新する（要件定義書5章 No.7）
- グラフはChart.js（円グラフ）を使用し、カテゴリ別の割合を視覚的に表示する。表はグラフの補足として同じ内訳データを金額付きで表示する
- 対象カテゴリの記録が0件の月は「データがありません」を表示し、グラフは非表示にする

## 6. 共通事項

- 通信中（API呼び出し中）はローディング表示を行い、二重送信を防ぐためボタンを非活性にする
- APIエラー時は画面上部または該当箇所にエラーメッセージを表示する（500系エラーは「予期しないエラーが発生しました」等の汎用メッセージ）
- レスポンシブ対応（スマートフォン表示）は要件定義書7章の通り対象外とし、PCブラウザでの表示を前提としたレイアウトとする
